FEB 01, 2024
Laravel Livewire Kubernetes Go Architecture

Technologies I Am Investing in 2024

I love APIs, but client apps suck. Why I am completely retiring React and Remix.run in favor of Laravel + Livewire, and keeping microservices lean on Kubernetes.

As it turns out, I am bad at blogging, who knew? (I knew, since like literally one of the first piece of code I wrote everytime I learn a new language/stack is a blog and I have a blog since 2003 but I am still hopeful like an idiot everytime I put up a new blog, I will write lots of posts.)

But I think this is a good concept, like yearly themes: setting some tech stacks as key points and goals is a good way for me personally to look back and see a clear timeline.

I love APIs but client apps suck

I think the first app I broke apart from a single full stack monolith to a server-side API + client-side app was Poltio's social network application back in 2015 or 2016.

Back then, the idea of having a client app where you can just keep a couple of static files (HTML, JS, and CSS) and host it on easy-to-scale storage buckets like AWS S3 was amazing. Like all good things, we put too much stuff in our client bundles and made everything more complex and worse.

With how things are going in client-side worlds (Next.js, Remix), full stack applications are coming back hard—and they SHOULD. Sending HTML generated dynamically on the server with minimal CSS and JS required for that route is simply the best way for web applications.

So after watching Next.js and Remix re-discover basic HTTP and web concepts 20+ years later, I am completely giving up and removing React, Vue, and their hormonal fullstack counterparts from my primary stack. We replaced our Next.js apps with Laravel + Livewire. So no more Next/Remix for me, thanks for all the fish.

Small Services & Kubernetes

I love DevOps, Kubernetes, and writing isolated services. But I don't like to overcomplicate things to the point where small teams struggle to understand what is going on. Since I use Kubernetes everywhere these days, deploying an isolated service internally or externally is seamless.

AUG 20, 2022
Neovim Lua Tmux Vim

My New Neovim Setup with 100% Lua

Switching a 15+ year Vim workflow to Neovim and rewriting everything in pure Lua. Why terminal + Tmux beats any graphical IDE for multi-service productivity.

I love Vim. It gives me the exact same development environment via SSH whether I am on my main workstation, an iPad, or a server I don't normally touch. But I can't use VSCode or any non-terminal editor thanks to Tmux. I need 3-4 panes open next to my editor, replicated across all the microservices I am actively building.

Even though I've tried every editor, Vim remained my daily driver for 15+ years. When I switched to Neovim, I was still hauling old Vimscript configs. I finally rewrote the whole configuration cleanly in 100% Lua using modern Lua-native plugins, built-in LSP, and Null-ls.

Configuring plugins and settings in Lua is vastly cleaner, faster, and more modular.

AUG 17, 2022
Hugo Static Sites Infrastructure

Hello Hugo & The Static Shift

Retiring an un-upgradeable Ubuntu VM hosting Ghost in favor of zero-maintenance static architecture hosted on GitHub Pages.

The old server that used to host my blog was a virtual machine running an older version of Ubuntu powered by Ghost. Since I forgot to upgrade that machine for a while, doing release upgrades became an absolute pain.

With something static, I don't need to babysit a database or patch a VM operating system just to host thoughts—I can just trust a global CDN and static hosting. Less maintenance means more time building things that actually matter.
